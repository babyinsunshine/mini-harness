## 真实工具与恢复

在独立临时目录中放置有错误的 `calc.py`：`add(a, b)` 返回 `a - b`。
通过实际 CLI 发起请求，观察到模型依次调用：

1. `read_file` 读取 `calc.py`
2. `edit_file` 将返回表达式改为 `a + b`
3. `write_file` 创建 `verify.py`
4. `bash` 执行 `python3 verify.py`

验证脚本断言 `add(2, 3) == 5`、`add(-1, 1) == 0`，输出 `TEST_OK`。
CLI 退出码 0，模型最终回复 `SMOKE_OK`。随后在 harness 外独立复跑验证脚本，
退出码仍为 0，输出 `TEST_OK`。

再次通过 CLI 的 `--resume` 恢复该会话。模型正确说明修改了 `calc.py`、
创建了 `verify.py` 以及先前的测试结果，退出码 0。

这两个 CLI 阶段的消息 usage 合计：输入 8047 token，输出 339 token。
此数值不包含后续压缩调用，不能作为整个验证过程的总费用或总用量。
