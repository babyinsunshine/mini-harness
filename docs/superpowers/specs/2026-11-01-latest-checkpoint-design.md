# 只保留最新检查点

本次对话已决定：默认只保留最新有效状态，不再累积每一步的历史快照。

- 每个 thread / namespace 独立保留最新一份检查点。
- 新快照的写入和旧快照、旧 writes 的清理在同一 SQLite 事务内完成。
- 最新检查点关联的 pending writes 必须保留，中断恢复不重放已执行工具。
- 打开旧会话时按同样规则整理，保留当前对话、图片、运行元数据和 transcript。
- 使用一个小型检查点连接封装与 SQLite 触发器；agent loop 沿用原实现。
- 本轮不增加历史模式开关，不修改图片消息格式，不迁移或删除用户真实会话。
- DELETE 后的文件空闲页由后续写入复用；已有大文件的物理回收可另行执行 VACUUM，不在每一步执行。

完整历史方便时间旅行，但本项目选择以恢复最新会话为主；旧 checkpoint_id 不再作为恢复入口。
