# Windows MCP 可用性改进

目标：让 WSL 中的 harness 稳定操作 Windows，保持两个通用 MCP 工具和现有 agent 循环。

## 方案与取舍

先修现有服务；实测仍失败时再替换。候选为 CursorTouch/Windows-MCP 固定提交
`94b52cfb48076cb793e710351517fa18a316cd12`，包含 UIA 超时和控制状态传播修复。
已用独立测试窗口验证切换、三轮中文输入和点击、截图及 UI 树；没有再现控制等待错误。
因此本轮沿用该提交，使用 `relaxed` 控制策略，保留直接输入的控制保护。
备选 sbroenne/mcp-windows 需要额外安装和重新验证，目前没有切换的收益证据。

## 改动边界

- `list_mcp_tools(server)` 只返回名称和简短描述；指定 `tool_name` 后返回完整说明和 schema。
  第一次真实模型测试为了读取被截断的完整目录多用了两次 Bash，这个调整减少无效往返。
- `call_mcp_tool(..., include_images=False)`：默认仍返回图片路径；视觉模型可主动选择
  在同一次结果中接收标准图片块。文字、结构化数据和超长输出落盘保持原有行为。
- 图片原始字节按哈希落盘，与 `read_image` 使用同一命名方式，避免再次查看时复制一份。
- Windows 示例使用固定源码提交、本机预装缓存和 `relaxed`；不关闭桌面控制保护。
- 只定向屏蔽已知弃用警告；不新增通用重试、超时升级、图节点或依赖。
- 实际密钥、Windows 用户目录、私有配置、截图、会话和测试日志不提交。

## 验证

真实 MCP 子进程回归验证图片到达模型、默认行为兼容、长文字与结构化数据未丢失、
相同图片不重复落盘。再用真实模型操作自建测试窗口，核对实际输入和点击结果；
不操作已有帖子或文档。完整测试及一次独立审阅通过后创建草稿 PR，不自动合并。
