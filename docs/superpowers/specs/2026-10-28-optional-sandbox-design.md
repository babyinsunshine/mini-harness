# 可选文件沙箱设计

状态：设计已确认。目标平台为 Linux / WSL2。

## 目标与已确认的规则

为学习用 harness 增加可选的文件访问边界，保持代码短小、易读。

- 默认关闭；用户开启后，工具只能修改初始项目目录及其子目录。
- 初始目录使用现有 `project_root`；`cd` 和恢复会话不扩大该边界。
- 默认可以读取用户本来有权读取的文件，网络使用宿主网络。
- 用户配置中的禁止访问路径同时禁止读取和写入，优先于普通目录授权。
- 模型可以申请额外目录的写权限，用户批准后供本次运行的后续调用使用。
- 用户可以决定是否开放申请通道、是否允许申请一次性绕过。
- 额外授权仅保存在内存；退出后清除，恢复会话重新申请。
- 主、子智能体共用这份规则和额外授权，通过主会话请求用户批准。
- MCP 本次不增加沙箱专用审批规则，沿用现有权限模式。

## 方案取舍

推荐：每次 Bash 调用由 Bubblewrap 启动受限进程；文件工具共用路径策略。
Session 关联策略，实际规则和授权由运行时对象持有，不增加 LangGraph 节点。
网络不创建独立 namespace，因此不同调用可以访问同一宿主开发服务。

另一种方案是长期运行一个沙箱工具服务，把所有文件操作都放进受限进程。
它能提供更统一的操作系统边界，但需要新增通信、服务生命周期和恢复机制。
本次选择较小的方案；文件工具的路径检查属于应用层约束，不冒充操作系统隔离。

## 配置建议

- `--sandbox` / `--no-sandbox` 控制开关，`--sandbox-config PATH` 显式指定 JSON 文件。
- 不自动信任仓库提供的沙箱配置；未指定配置时使用内置默认值。
- 恢复会话沿用原项目根目录和保存的启动设置；指定的用户配置重新读取。
- 配置或 Bubblewrap 不可用时明确报错，不静默关闭已开启的沙箱。

建议的最小 JSON：

```json
{
  "deny_paths": [],
  "allow_write_requests": true,
  "allow_bypass": false
}
```

`deny_paths` 先只支持明确的文件、目录路径，不支持 glob。展开 `~`，相对路径以配置文件目录为基准。
策略检查使用规范化绝对路径，目录规则覆盖其子目录；实现不得把路径字符串前缀当作目录关系。
文件或目录的禁止规则也作用于项目内路径。路径如何遮蔽、缺失路径如何明确报错，留给实现选择，不能静默忽略规则。
普通授权不能开放禁止访问路径；在沙箱启用时，普通工具也不能修改用户沙箱配置文件。

## 写入范围与必要通道

工具默认可写范围为项目目录，随后叠加批准的额外目录。Bash 保留原绝对路径，继续支持现有 cwd 衔接。

逐项列出的例外：

- 通过 `TMPDIR` 提供独立临时空间，宿主 `/tmp` 仍按原路径只读可见，不承诺不同调用共享临时文件。
- 当前会话的 `env.sh` 保留可读写能力，保持已有的环境配置功能；子会话使用自己的 `env.sh`。
- 日志输出和 cwd 回传保留专用通道，不因此开放整个会话目录供命令修改。
- SQLite、transcript 和 artifacts 等管理数据由沙箱外的 harness 写入。
  会话管理目录即使位于项目内也保持只读，防止篡改保存的启动配置和权限边界。

禁止路径优先于 `env.sh` 等工具访问例外。缓存写入失败时，可将缓存指向项目内，或申请额外目录；不自动开放用户主目录。
继续过滤传给 Bash 的模型密钥，沙箱不承担自动清理所有环境变量的承诺。

## 审批与生命周期

拟增加一个工具 `request_sandbox_access(paths, reason)`，申请具体目录的会话级写权限。
CLI 展示规范化目录、原因和有效期；批准后才更新内存授权，拒绝则返回工具错误。

Bash 拟增加 `bypass_sandbox` 和说明原因的参数，申请仅本次调用在沙箱外执行。
配置允许申请、用户批准这次请求后才执行；不自动重试失败的命令。
完整绕过会解除本次命令的文件沙箱限制，包括禁止路径，审批必须明确显示这一点。
绕过只影响该次命令及其子进程，不修改默认策略和下一次调用。

`--full-access` 继续跳过普通工具审批，但不关闭沙箱，也不自动批准沙箱扩权或绕过。
会话信任、其他工具的已有批准也不替代这两类明确授权。
非交互模式或无审批回调时拒绝需要用户批准的申请，不等待无法提供的输入。

额外授权可影响新调用；已运行命令保留原限制，不尝试修改其 namespace。
审批记录可以写入日志，但日志、历史工具结果和恢复检查点都不能恢复有效授权。
审批固定规范化路径，执行前重新确认其目标；保护禁止路径、配置和管理目录的可写祖先，避免重命名绕过。
Bubblewrap 的真实入口在启动时固定并保持只读，不在每次执行时重新信任 PATH 中的新程序。
旧对话中的授权文字也不能替代运行时权限；恢复后的提示需明确额外授权已经清除。
新增或更换用户配置的禁止规则，不追溯清除历史上下文或已有输出文件中的内容。

## 覆盖范围

- Bash：操作系统层面的文件边界，正常启动的子进程继承。
- 文件工具：读写前检查同一份路径策略，文件锁和版本检查继续保留。
- Skill 加载、AGENTS.md 注入、压缩后的文件回读：向模型提供内容前遵守禁止读取规则。
- MCP：服务端在独立进程或远端执行，不受 Bash 沙箱约束，不能宣称其文件操作受项目写入边界保护。
  开启 sandbox 不额外强制审批 MCP；沿用现有权限模式，`--full-access` 下仍可直接调用。

本次实现是本地文件访问沙箱，保留宿主网络；不提供容器镜像、域名过滤、资源配额或文件回滚。
WSL 执行桥接入口 `/init`、`/run/WSL` 在沙箱内作为内置禁止路径，防止 Windows 进程脱离 Linux 边界。
MCP 和通过宿主网络调用的外部服务属于单独的访问边界。

## 模块与验证

用一个小模块封装策略、授权和 Bubblewrap 参数；复用现有工具工厂、权限入口、进程管理和 CLI 审批。
不新增图节点、常驻执行器、授权数据库表或自动放宽策略的兜底。
具体类名、JSON 字段的校验方式和参数生成细节由实现决定，优先可读性。

验证需要覆盖：开关、项目外写入拒绝、禁止路径、符号链接、文件工具和自动回读的一致性；
会话级授权、拒绝、完整绕过、`--full-access` 与无交互模式；
主子会话共享授权与重启清除；cwd、env.sh、日志、stdin、后台服务和停止进程树的兼容性。
真实 Bubblewrap 集成测试仅在依赖和系统能力具备时运行；其余环境给出明确跳过原因。
