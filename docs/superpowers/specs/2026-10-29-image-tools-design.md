# 简单图片读取与历史清理

用户已选择：新增 `read_image(path)`；近期图片保留，旧图片整块移除并留下固定提示和原图路径，需要时重新读取。项目以代码简洁、易读为先。

## 范围与取舍

- 独立图片工具，复用文件权限和文件锁；不增加图节点或依赖。
- 初版只接收 PNG/JPEG，通过文件头识别，最多读取 5 MiB；不实现完整图片解码校验、缩放、OCR、自动描述或 CLI 附件。
- 原始字节按内容哈希保存到当前会话 `artifacts/`，工具结果包含保存路径和 LangChain 标准图片块。恢复会话复用原来的图片结果，不重新读取可能已变化的源文件。
- MCP 继续保存截图并返回路径，模型按需调用 `read_image`。
- 默认模型不变。使用图片需要模型/API 支持视觉输入；不会自动切换供应商或调用额外模型。

## 消息与压缩

- 图片作为工具结果保存在图和会话中。发起主请求时，把一组工具结果中的图片集中放到其后的 HumanMessage，工具结果本身保留文字和调用关系，兼容只允许 user 消息携带图片的接口。转换不修改保存的历史。
- Micro 复用近期轮数、近期 token、批量节省量和空闲时间策略；图片候选保留文字，仅将完整图片块替换成固定重读提示。清理结果复用消息 ID，不修改原图。
- 摘要输入只序列化文字和图片路径，不序列化 Base64；摘要保留先前模型的观察结论，不为图片额外发起描述请求。
- 图片按每张 4096 token 粗估，不将 Base64 当文字计数；沿用 API usage 校准和已有超限恢复。这是容量启发值，不是供应商计费或精确上界。

## 已讨论的方法

采用整块清理和磁盘引用，机制与现有工具清理一致。读取时缩小图片会影响小字细节；单独调用模型描述每张图片会增加请求和代码，初版都不采用。

## 验证

真实临时图片与 Session、文件权限、LangGraph、SQLite；外部模型调用以离线模型或本地 HTTP 服务替代。检查 PNG/JPEG、过大/不支持输入、拒绝访问、恢复图片、请求消息顺序、近期保护、旧图清理、固定引用和摘要不含 Base64。无真实视觉 API 验证时明确说明。
