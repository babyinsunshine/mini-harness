# MCP schema 按需查询与参数反馈

用户已确认：保持两个通用 MCP 工具，批量读取本次任务所需 schema；执行前校验参数，
不合法时直接附错误与对应 schema，合法时只执行一次。schema 缓存在程序内，不自动注入系统提示。

## 取舍

全量 schema 放入系统提示会持续占用上下文；解析远端错误字符串又依赖不同服务器的格式。
采用批量查询加本地 JSON Schema 校验，复用 MCP 依赖已经使用的 jsonschema，并在可选依赖中明确声明。
代码集中在 `tools/mcp.py`，复用图的异常反馈和 Session 的长文本落盘，不增加工具、节点或自动重试。

## 接口与行为

- `list_mcp_tools(server=None, tool_names: list[str] | None=None)`：无 server 时列服务器；
  无 tool_names 时列简短目录；指定列表时按请求顺序返回完整说明与 schema。
  单个工具也用一个元素的列表；迁移原来的 tool_name 参数，不维护两套查询入口。
  空列表返回空列表，重复名称只返回一次；未知名称报错，避免静默遗漏。
- 当前工具集合首次发现或调用时获取目录，缓存到闭包字典。只在内存保存；重新打开会话重新获取。
  缓存按服务器隔离，不进入 State、SQLite 或系统提示；本轮不做动态目录更新机制。
- `call_mcp_tool` 使用对应 input_schema 校验原始 arguments，不转换、补齐或猜测字段。
  错误反馈明确“本次未执行”，包含错误字段、原因和对应 input_schema；长反馈照常落盘。
  正确参数原样传给 MCP 一次；执行错误和取消继续交给原有流程，不混同参数错误。
- MCP 仍是可选依赖；不开启 MCP 的基础安装不能因为 jsonschema 导入而失败。
